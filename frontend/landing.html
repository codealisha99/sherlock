Codebase intelligence

Read a codebase like a detective reads a case file.

Paste a GitHub repository. Sherlock builds a code graph and vector embeddings, scans for vulnerabilities and code-quality hotspots, checks dependencies against the OSV vulnerability database, and lets you ask questions about any file, function or class.

Repositories on github.com. Sherlock makes a shallow clone and reads the code.

How it works

From URL to answers in four steps.

Each step runs on the server against a shallow clone. You watch progress in the workspace and can stop reading at any point.

  1. 1

    Paste a URL

    Give Sherlock a github.com repository. It makes a shallow clone with size limits.

  2. 2

    Build the graph

    Files, classes, functions, methods and imports become a code graph for Python, JavaScript, TypeScript, Go, Java, Rust and Ruby. Code chunks get vector embeddings for search.

  3. 3

    Scan the code

    Security rules, secret detection, dependency checks against the OSV database, and quality metrics such as complexity and test gaps.

  4. 4

    Explore, verify and ask

    Click any node to see its findings and source. Have a model verify findings, and chat with the repository, scoped to that node, with citations.

Features

Everything you need to get oriented in a new repo.

Graph

Interactive AST graph

Navigate files, classes, functions and their calls and imports. Filter by health, follow edges, and jump to the source line.

Security

Vulnerability scanner with CWE mapping

Findings carry a severity, a snippet, a recommendation and a CWE identifier where one applies, so you can triage with a shared vocabulary.

Quality

Lagging-code hotspots

See where complexity, file size and missing tests concentrate. Hotspots show up on the graph, not buried in a report.

Dependencies

Dependency CVE checks

Versions pinned in your manifests and lockfiles are checked against the OSV.dev vulnerability database. Each finding lists its advisory IDs and the fixed version when one is known.

Verify

AI verification of findings

A model gives each checked finding a verdict (confirmed, likely, false positive or uncertain), a confidence score, an explanation and a suggested fix. Use your own key, or the platform model within your plan's limits.

Languages

Python, JavaScript/TypeScript, Go, Java, Rust, Ruby

Classes, functions, methods, imports and simple call relationships appear in the graph for each supported language, with the same filters, search and node details.

Chat

Chat on any node

Ask why a function exists or how a flow works. Answers cite the files they came from, and the chat is scoped to the node you are viewing.

Keys

Bring your own API key

Use OpenAI, Anthropic, Groq, OpenRouter or any OpenAI-compatible endpoint. Your key is used for your requests only.

Privacy

Private to your account

Repositories, findings and chats belong to the account that created them. Other users cannot list or open them.

Security

Built to handle code you did not write.

Repositories are untrusted input. Sherlock treats them that way at every step, from the clone to the answer a model gives you.

  • Encrypted API keys. Bring-your-own keys are encrypted at rest with a server-side master key. They are decrypted only in memory when a request needs them, and are never shown again after you save them.
  • Hashed passwords. Passwords are stored with scrypt and a per-user salt. Session tokens are random and only their hash is stored.
  • Rate limiting. Sign-in, analysis, chat and webhook endpoints each have their own per-IP or per-account limits. Repeated failed logins lock the account for a short period.
  • Prompt-injection defense. Questions are screened before they reach a model. Repository content is fenced as data, not instructions, before it is sent as context.
  • Safe cloning. Only https://github.com URLs with a strict owner and repo format are accepted. Clones are shallow, run without git hooks, and are capped in size. Symlinks are not followed.
  • Isolated repositories. Every repository, job, finding and chat session is scoped to the account that owns it.

FAQ

Questions people ask first.

Which repositories can I analyze?

Repositories hosted on github.com. Enter the full URL, for example https://github.com/owner/repo. Repositories that the server cannot clone are reported as failed analyses with the reason shown.

Which languages are supported?

Python is parsed with the standard library AST. JavaScript, TypeScript, Go, Java, Rust and Ruby are parsed with tree-sitter to extract classes, functions, methods, imports and simple calls, with pattern matching as a fallback. Dependency checks cover the manifests and lockfiles Sherlock recognizes.

Do I need my own API key?

No. Without a key, chat and AI verification use the platform model when one is configured. If you add a key, your requests use it instead and count against your provider account, not our quota.

When is my code sent to a model?

Repository analysis runs on Sherlock's servers and does not call a model. Code is sent to a model provider only when you ask a chat question or verify a finding, and then only the context for that question or finding is included, fenced as untrusted data.

What counts toward my limits?

Each repository analysis counts once toward the monthly analysis limit. Each question you send in chat, and each finding verified with AI, counts toward the daily chat limit. Limits and usage are shown in Settings.

How do I upgrade or cancel?

Upgrade from Settings. Payments are handled by Stripe Checkout, and your plan updates once payment is confirmed. Plan changes and billing history are in Settings under Billing.
