The problem

Reading a new codebase starts blind.

Without Sherlock

  • Grep for an entry point and follow imports by hand.
  • Open files one at a time and lose the thread between them.
  • Guess which module matters, and which one is quietly unsafe.
  • Skim the test folder to see what is covered.

With Sherlock

  • One map of files, classes, functions and calls.
  • Findings pinned to the nodes they belong to.
  • Questions answered with citations to the files they came from.

How it works

Six stages build the map. Then you ask.

Each stage runs on the server against a shallow clone. You can watch progress in the workspace and stop reading at any point.

  1. 01

    Cloning

    Shallow clone of a github.com repository, size-capped, with git hooks disabled.

  2. 02

    Indexing

    Files, classes, functions, methods, imports and calls parsed for seven languages.

  3. 03

    Embedding

    Code chunks get vector embeddings for search.

  4. 04

    Scanning

    Security rules with CWE IDs, secret detection, complexity, file size and missing tests.

  5. 05

    Checking dependencies

    Manifests and lockfiles checked against OSV.dev advisories.

  6. 06

    Graphing

    Findings are mapped onto the graph nodes they belong to.

  7. 07

    Explore & ask

    Open any node and its source, verify findings with a model, and chat with citations.

Languages
Python is parsed with the standard library AST. JavaScript, TypeScript, Go, Java, Rust and Ruby are parsed with tree-sitter, with pattern matching as a fallback.
Model providers
Bring your own key for OpenAI, Anthropic, Groq, OpenRouter or any OpenAI-compatible endpoint, or use the platform model within your plan.
Privacy
Repositories, findings and chats belong to the account that created them. Code goes to a model only when you ask a chat question or verify a finding, and only that context is sent.

Security

Built to handle code you did not write.

Repositories are untrusted input. Sherlock treats them that way at every step, from the clone to the answer a model gives you.

Encrypted API keys
Bring-your-own keys are encrypted at rest with a server-side master key. They are decrypted only in memory when a request needs them, and are never shown again after you save them.
Hashed passwords
Passwords are stored with scrypt and a per-user salt. Session tokens are random and only their hash is stored.
Rate limiting
Sign-in, analysis, chat and webhook endpoints each have their own per-IP or per-account limits. Repeated failed logins lock the account for a short period.
Prompt-injection defense
Questions are screened before they reach a model. Repository content is fenced as data, not instructions, before it is sent as context.
Safe cloning
Only https://github.com URLs with a strict owner and repo format are accepted. Clones are shallow, run without git hooks, and are capped in size. Symlinks are not followed.
Isolated repositories
Every repository, job, finding and chat session is scoped to the account that owns it.

FAQ

Questions people ask first.

Which repositories can I analyze?

Repositories hosted on github.com. Enter the full URL, for example https://github.com/owner/repo. Repositories that the server cannot clone are reported as failed analyses with the reason shown.

Which languages are supported?

Python is parsed with the standard library AST. JavaScript, TypeScript, Go, Java, Rust and Ruby are parsed with tree-sitter to extract classes, functions, methods, imports and simple calls, with pattern matching as a fallback. Dependency checks cover the manifests and lockfiles Sherlock recognizes.

Do I need my own API key?

No. Without a key, chat and AI verification use the platform model when one is configured. If you add a key, your requests use it instead and count against your provider account, not our quota.

When is my code sent to a model?

Repository analysis runs on Sherlock's servers and does not call a model. Code is sent to a model provider only when you ask a chat question or verify a finding, and then only the context for that question or finding is included, fenced as untrusted data.

What counts toward my limits?

Each repository analysis counts once toward the monthly analysis limit. Each question you send in chat, and each finding verified with AI, counts toward the daily chat limit. Limits and usage are shown in Settings.

How do I upgrade or cancel?

Upgrade from Settings. Payments are handled by Stripe Checkout, and your plan updates once payment is confirmed. Plan changes and billing history are in Settings under Billing.
